> 视觉方向来源：`archivebate` 设计系统（温暖纸张 / 赤陶主色 / 硬偏移阴影 / 零圆角）
> 文档版本：2026-10-04

本文档讲**布局、层级、视觉语言与源码取舍**；**功能交互的行为与状态流转**（触发 → 状态变化 → 可见反馈、状态迁移表、存储键口径）见配套的 `deepssh-interaction-spec.md`，供开发对码使用。

**原型与本文档是设计源，`/projects/deepssh` 是当前实现基线。** 设计允许超出源码——超出部分不是文档写错，而是**尚未实现的新交互**；它们集中在第 11 章，逐条标明落地时 Rust / frb 侧要配合的改动。反过来，本文档描述了而原型没画出来的交互，就是缺口，必须补画或删除，不能留在文档里当设计。

字段名、存储键、状态结构这类**已落地部分的语义以源码为准**；本文档与原型描述的是**目标形态**。源码基准见文首，基准之后的源码变更不会自动同步到本文档。

## 1. 产品定位

DeepSSH 是一个本地桌面 SSH 工作台：左侧资源管理器聚合 SSH 配置与已打开会话，右侧是终端舞台；配套 SSH 配置管理、端口转发、主题配置三个设置模块。

原型覆盖 4 个用户可见页面，对应源码的 4 个 `WorkbenchContentMode`：

| 原型页面 | 源码位置 | 职责 |
|---|---|---|
| 工作台 | `lib/workbench/workbench_page.dart` | 会话浏览 + 终端 + 运行态观测 |
| 连接配置 | `lib/features/ssh_profiles/ssh_profiles_page.dart` | SSH 配置的增 / 删 / 改 / 连 |
| 端口转发 | `lib/features/tunnels/tunnel_configs_page.dart` | 隧道的增 / 删 / 启停 |
| 主题配置 | `lib/features/theme_config/theme_config_page.dart` | 界面与终端外观、正则高亮规则 |

## 2. 设计系统

### 2.1 颜色令牌

原型 `:root` 中的六个主令牌（来自 archivebate，锁定不漂移）：

| 令牌 | 值 | 用途 |
|---|---|---|
| `--bg` | `#FAF9F5` | 页面底色（暖纸白） |
| `--surface` | `#FFFFFF` | 卡片 / 面板 |
| `--fg` | `#1F1E1D` | 主文字、边框、阴影源 |
| `--muted` | `#6B6862` | 次要文字、等宽标签 |
| `--border` | `#E9E5DA` | 常规描边 |
| `--accent` | `#D97757` | 唯一强调色（赤陶） |

状态与终端色：

```
--ok #4E7A4E   --warn #8A6414   --warn-bar #C08A2E   --danger #B0523A
--term-bg #17181A  --term-fg #DEDCD6  --term-dim #86847C
--term-green #8FBF7F  --term-blue #7FA8D8  --term-amber #D9A24B
--term-red #D98C7A    --term-cyan #6FB6B0
```

派生色一律用 `color-mix(in oklch, …)` 生成，不允许在组件里写死新的十六进制值：

```
--accent-ink   color-mix(in oklch, var(--accent) 68%, var(--fg))
--accent-soft  color-mix(in oklch, var(--accent) 14%, transparent)
--ok-soft / --warn-soft / --danger-soft / --fg-soft
```

> 注意：源码 `lib/core/theme/app_colors.dart` 当前是 VS Code Dark 深色主题（`#1E1E1E` / `#3794FF` / 圆角 6px）。本次重新设计**只改原型**，落地时需要单独决定是否把 Flutter 端主题一并换成这套浅色令牌——这是产品决策，不是设计细节。

### 2.2 字体

| 角色 | 栈 |
|---|---|
| 展示 / 标题 | `Georgia, 'Iowan Old Style', 'Charter', 'Times New Roman', serif` |
| 正文 | `-apple-system, 'PingFang SC', 'Microsoft YaHei', 'Noto Sans CJK SC', system-ui, sans-serif` |
| 等宽 / 数字 / 标签 | `ui-monospace, 'JetBrains Mono', 'SF Mono', Menlo, Consolas, monospace` |

规则：所有小节标题、状态标签、字段名一律等宽 + 大写 + `letter-spacing: .1em~.14em`；正文与数据用无衬线；只有页面级标题与空态主文案用衬线。终端内容与其配置中的正则、色值必须用等宽。

### 2.3 四条形状规则（视觉语言的全部来源）

1. **零圆角**：所有元素 `border-radius: 0`，包括输入框、按钮、色板、弹窗。
2. **硬偏移阴影**：`--shadow-hard`（2px 2px 0，20% 墨色）用于可点击卡片、悬浮层；`--shadow-solid`（2px 2px 0 全墨）用于对话框与抽屉。禁止模糊阴影。
3. **像素按压**：按钮 `:active` 时 `transform: translate(1px, 1px)`，阴影同步消失，形成物理按压感。
4. **方形状态点**：状态一律用 8–10px 实心方块 + 1px 墨色描边表达，不用圆点、不用 emoji。

## 4. 工作台

### 4.1 布局模型

`.bench` 是一个**高度确定**的纵向 flex 容器，高度为 `calc(100dvh - var(--bench-chrome))`，`--bench-chrome` 由 JS 实测顶栏高度加 `.main` 上下内边距得到；`min-height: 620px` 兜底短屏。

> 这是必须的：只有容器高度确定，`flex: 1 1 auto` 才有可分配的空余空间，上下两块才会真正「此消彼长」。若只用 `min-height`，拖动只会把页面整体撑高，上方终端尺寸不变。

```
.bench (column, 高度确定)
├── .term-wrap   flex: 1 1 auto   min-height: 0   ← 终端舞台 + 状态栏
├── #dockSplit   7px  水平分隔条（上下拖动）
└── .docks       flex: 0 0 var(--dock-h)
    ├── #dockEvents  flex: 0 0 var(--dock-events-w)
    ├── #dockVSplit  7px  竖向分隔条
    └── #memoryDock  flex: 1 1 0
```

横向：`Explorer │ #sbSplit │ 终端`。

### 4.2 分栏拖动规格

| 分隔条 | 方向 | 范围 | 步进 | 特殊行为 |
|---|---|---|---|---|
| `#sbSplit` | 水平拖动 | 56 – 560px（默认 280） | 键盘 ←/→ 各 16px，Home/End 到端点 | 拖到 ≤64px 自动进入图标轨 |
| `#dockSplit` | 垂直拖动 | 96 – 420px（默认 280） | 键盘 ↑/↓ 各 16px，Home/End 到端点 | 拖到 <72px 自动收起 |
| `#dockVSplit` | 水平拖动 | 260px – 容器宽 − 220px | 键盘 ←/→ 各 16px | 上限动态计算，保证内存面板不窄于 220px |

规则：

- **分隔条中心永远贴着指针**：`dock 底边 − clientY − 分隔条半高`。不要用「按下时记锚点 + 位移量」的模型，收起/展开时会跳位。
- 拖动中给分隔条加 `aria-valuenow`；`role="separator"` + `tabindex="0"`，键盘方向键必须等价于拖动。
- 底部面板收起时只保留 37px 标题条，分隔条与内存面板一起退出布局；反向拖动即按指针高度展开，不跳位。
- 分隔条 hover / 焦点态只改变背景与描边，**不得**降低文字对比度。
- ≤980px：`.workbench` 纵向堆叠，`.split.v` 与 `#dockVSplit` 隐藏，底部两块改为纵向排列（高度仍由 `--dock-h` 控制，拖动继续有效）。

### 4.3 Explorer 资源管理器（对齐 `host_tree.dart`）

结构自上而下：

1. 头部：标题 + 「新增连接 ▾」下拉。
2. **SSH 配置分区在前**，每个已打开会话的配置一个分区：`connectionGroupId` 决定分组色条（蓝 / 琥珀 / 墨三色），标题为配置名，**不带状态标签、不带折叠箭头之外的装饰**；分区可折叠，折叠状态存内存即可。
3. 分区内是已打开的会话行。**分区没有空态**：关闭该配置下最后一个会话时，整个分区随之从树里移除，toast 提示「已关闭 SSH 会话 X，配置「prod-web-01」已从 Explorer 移除」。所有分区都被移除后，树区显示空态：26px 线性图标 + 等宽「暂无已打开的会话」+ 辅助文案「从右上角「新增连接」打开一个终端」。
4. **`Local` 分区默认排在最后**，同样可折叠、同样遵循「最后一个会话关闭即移除」；新建本地终端时若该分区已被移除则重新创建并追加到末尾。
5. **分区顺序可拖动**：标题左侧是 6 点拖动柄（对齐 Flutter `ReorderableListView` 的 `ReorderableDragStartListener`，与正则规则行同一枚手柄）。按住拖动时分区跟随指针、虚线框标示落位、靠近树区上下边缘自动滚动；松手后重排、toast「已把「X」移到第 N 位」、焦点移到新位置的拖动柄。键盘等价操作 `Alt/⌘ + ↑/↓`；`aria-label` 随位置重写为「当前第 N 项，共 M 项」。拖动柄使用 `Pointer Events + setPointerCapture`（含能力检测降级），禁止 `scrollIntoView`。
6. **块内会话顺序也可拖动**：每个会话行左侧是同一枚手柄的紧凑版 `.ex-sgrip`，**落位范围限定在该行所属的 `.ex-items`**——会话只能在同一配置内换位，不会被拖进别的配置。交互与分区排序同构（跟随指针、虚线落位框、松手 toast、焦点回握把、`Alt/⌘ + ↑/↓` 键盘排序），差别只有两点：握把用负外边距藏进行自身的左内边距，因此图标与名称的对齐不变；虚线框左右内缩到行盒宽度。复制会话、关闭会话、新建本地终端后，块内握把编号立即重算。

会话显示名规则（`ssh_session_item.dart` / `local_terminal_item.dart` / `terminal_state.dart`）：

```
SSH 会话：note → previewLabel → title
本地终端：note → title
```

会话行左侧 3px 竖条表示连接状态色；**右侧有悬停显形的关闭按钮 `.ex-x`**——行为与右键菜单「关闭 SSH 会话 / 关闭终端」完全一致：移除会话行、连带关闭标签页、并在清空该配置时移除整个分区。按钮平时 `opacity:0`，行 hover 或按钮自身持有焦点时显形，因此键盘用户 Tab 到它时看得见；点击 `stopPropagation`，不会连带打开会话；图标轨（≤96px）下隐藏。

**右键菜单**（对齐 `_showSshSessionMenu`）：

| 对象 | 菜单项（顺序固定） |
|---|---|
| SSH 会话 | 编辑备注 / 复制 / 关闭 SSH 会话 |
| 本地终端 | 关闭终端 |

菜单规格：宽 150px、项高 32px、hover 出现 3px 赤陶色左边条、`Esc` 与点击外部关闭。复制会克隆会话行并新开一个标签页。编辑备注遵循显示名规则，保存后同步更新 Explorer 行与标签页标题。

**最小态（图标轨）**：宽度 ≤96px（`RAIL_MAX`，与容器查询 `@container ex (max-width:96px)` 一致）时，所有名称用裁剪隐藏（**不是 `display:none`**，读屏仍需可读），每个主机与会话保留图标；名称转为原生 `title` tooltip，拖宽后自动撤掉；分组身份由文字转为图标色 + 活动行左侧强调条；折叠提示、空态文案、页脚工具按钮全部按图标态排布并补 `aria-label`；**拖动柄隐藏**，树区空态只留图标。

页脚两个工具按钮中，「内存监控」是**真开关**：点击隐藏 / 展示底部内存面板，同步 `aria-pressed` 与提示文案，状态写入 `deepssh.memHidden`。隐藏时竖向分隔条一并退出布局，实时事件铺满整行。

### 4.4 终端区

- 标签条：可横向滚动，激活标签用底部 3px 赤陶条 + 墨色文字；右侧「+」新建本地终端；每个标签有关闭按钮，关闭最后标签时回到空状态。
- 空状态文案：「从左侧资源管理器打开一个终端」，配 30px 线性图标，垂直居中。
- 终端本体：深色舞台（`--term-bg`），ANSI 配色，等宽 14px。
- 状态栏：会话名 · 主机 · 端口 · 编码 · 连接状态方块。状态色用方形色块 + 等宽文字。

### 4.5 底部面板

- **实时事件**（左）：`INFO / WARN / ERROR` 三级流，**错误日志与普通事件同属一条流**，按时间倒序插在最前。等级靠左侧 3px 红 / 黄竖条 + 等宽芯片表达；面板变窄时芯片隐藏而非溢出。收起成 37px 标题条时，「最新」读数取列表第一条（含错误条目），保证与列表一致。
- **内存监控**（右）：单列指标列表（占用、进程数、线程数、示例数据徽标）。容器查询：<360px 隐藏「示例数据」，<290px 再隐藏「直播」徽标——**降级而不是溢出**。
- 两块各自内部滚动，互不影响。

## 5. 连接配置页

- 顶部一行：标题 + 说明 + 计数；右侧唯一主 CTA「新增 SSH 配置」（实心）。
- 工具行：搜索框（按名称 / 主机 / 用户名模糊匹配）+ 认证方式筛选**下拉框**（全部 / 密码 / 私钥 / Agent）。认证只有三种取值，不做分段控件。
- **行的信息分三层**，而不是传统的表头列：
  - 主行：名称 + 状态徽章（在线 / 已停止）+ 认证徽章（密码 / 私钥 / Agent）+ 终端类型徽章；
  - 副行：`用户名@主机:端口`，等宽字体、弱化；
  - 右侧「最近使用」纵向两块：上为标签，下为时间值。
- **「最近使用」口径**：记录最近一次**成功建立连接**的时间，仅查看配置不计入。同一天显示 `HH:MM:SS`，昨天显示「昨天 HH:MM」，更早显示「M 月 D 日」，从未连接过显示「从未连接」——「从未连接」不用等宽数字样式，用弱化文字表示，避免和真实时间戳混淆。
- **列表高度与滚动归属**：列表按**内容高度自适应**，不足一屏时不能留空白边框框，超出一屏时由页面整体滚动。落地时不要用 `Expanded` / 固定高度把表格撑满。
- 行操作：**连接**（文字按钮）、**编辑**、**删除**（删除必须走确认对话框，文案「删除后不可恢复」）。同一行不出现两个实心按钮。
- 搜索无结果时展示空状态而不是空白表格。

### 5.1 SSH 配置表单（抽屉）

字段与校验（对齐 `ssh_profile_form_page.dart`）：

| 字段 | 控件 | 校验 |
|---|---|---|
| 名称 | 文本 | 必填 |
| 主机 | 文本 | 必填，IP 或域名 |
| 端口 | 数字 | 默认 22，范围 1–65535 |
| 用户名 | 文本 | 必填 |
| 认证方式 | 下拉框 | 密码 / 私钥 / Agent |
| 密码 | 密码框 | 仅「密码」时显示 |
| 私钥路径 | 文本 + 浏览 | 仅「私钥」时显示 |
| 密钥标识 | 文本 | 仅「Agent」时显示，可留空表示用 agent 中的默认密钥 |

切换认证方式即切换可见字段——三选一，只显示当前方式的凭据区——切换时清空另一方式的凭据草稿。抽屉底部固定「取消 / 保存」，保存按钮为唯一实心主按钮。

抽屉底部另有一行凭据说明 `#sshCredHint`，随认证方式切换文案：密码＝「凭据仅保存在本机系统钥匙串中，不会写入项目文件」；私钥＝「私钥路径只保存在本机，不会随配置同步到其他设备」；Agent＝「凭据由本机 ssh-agent 提供，本应用不接触也不保存任何私钥」。

## 6. 端口转发页

- 列表列：状态方块 · 名称 · 类型（本地 / 远程）· 监听地址 · 目标地址 · 操作。
- 类型是行内分段控件（源码 `tunnel_config_item.dart` 的 `TunnelType`），切换即时生效。
- 每行一个启停开关：运行时显示「停止」，停止态显示「启动」；状态变更写事件流（见 §4.5）。
- 表单字段：名称 · 类型 · SSH 配置（下拉，来源为已保存 profile）· 监听地址 · 监听端口 · 目标主机 · 目标端口。监听端口被占用时在字段下方给出行内错误，不弹 toast。
- 当前三条隧道为示例数据。

## 7. 主题配置页

左右两栏（`.theme-grid`，≤980px 纵向堆叠）：左「界面主题」，右「终端主题」。

### 7.1 界面主题

预设方案下拉（见 §7.3）→ 字体族与字号 → 常规 / 加粗字重 → 配色样本（每个色板 = 色块 + 名称 + Hex，名称用等宽大写）。

### 7.2 终端主题

预设方案下拉（§7.3）→ 实时预览 → 光标（样式 / 闪烁）→ 终端配色 → **正则高亮**（见 §8）→ 回滚缓冲行数。

**实时预览不是装饰**：它按正则高亮规则的当前顺序与颜色实时着色，规则改动立刻反映。

### 7.3 预设方案下拉（两栏共用）

源码对应 `_PresetSelector`（`theme_config_page.dart`）：一个触发器 + 一个选项列表。本原型把选项做成**下拉框**，并且**每一行右侧都带删除按钮**。

**结构**

```
.psel[data-presets="ui|term"]        position:relative
├── .psel-btn[data-preset-toggle]    触发器，38px 高，通栏：16px 色块 + 方案名 + [自定义] 标签 + ▾
│     aria-haspopup="menu" aria-expanded aria-controls
└── .psel-menu[data-preset-menu]     绝对定位于触发器下方 4px，左右对齐，1px 边框 + 硬阴影
      ├── .psel-list[data-preset-list]           每行 = .psel-pick(选择) + .psel-del(删除)
      └── .psel-foot
            ├── .psel-add[data-preset-add]        末位固定：「＋ 新建自定义方案」
            └── .psel-restore[data-preset-restore] 有内置方案被隐藏时才出现：「↺ 恢复内置方案（N）」
```

- 行高 34px，`.psel-pick` 占满剩余宽度，`.psel-del` 为 28×28 图标按钮（垃圾桶），悬停 `--danger` + 1px 边框，`aria-label="删除方案 <名称>"`。
- 选中态：左侧 3px `--accent` 竖条 + `--bg` 底；行内 `aria-checked="true"`，切换按钮上的 `.p-tag`「自定义」仅对自定义方案显示。
- 列表可见顺序：**内置方案（按源码顺序）→ 自定义方案（按创建顺序）**。这一分组决定了副本的落位（见下）。

**交互契约**

| 操作 | 结果 |
| --- | --- |
| 点触发器 / 再次点击 | 展开 / 收起；展开后焦点落在当前选中行 |
| 点某行 `.psel-pick` | 该栏内单选，收起列表，焦点回触发器；终端栏额外按预设 id 替换高亮规则 |
| 点某行 `.psel-del` | 只删该行，**列表保持展开**，焦点落到新的当前选中行 |
| 点末位「＋ 新建自定义方案」 | 以当前面板设置新建 `自定义方案 N`（N = 该栏已有自定义数 + 1）追加到自定义组末尾并立即选中 |
| 右键某行 | 150px 菜单，单项「复制方案」；副本插到源项之后、继承色块、命名 `<原名> 副本` |
| 点「恢复内置方案（N）」 | 清空隐藏表，内置方案回到列表原位 |
| 点击列表外部 / `Esc` / `Tab` | 收起列表（`Esc`、`Tab` 同时把焦点交还触发器） |
| `↑ ↓ ← →` `Home` `End` | 在「所有行内控件 + 末位新建 + 恢复」这一条序列内循环移动焦点 |

**删除语义**

- 删除自定义方案：从 `deepssh.uiPresets` / `deepssh.termPresets` 移除该条，持久化生效。
- 删除内置方案：不销毁定义，只写入 `deepssh.uiHiddenPresets` / `deepssh.termHiddenPresets` 从列表隐藏，因此可以整栏删空再一键恢复。
- 删除的是当前选中项时：自动改选列表首个方案，并**套用该方案的设置**（终端栏会随之换成它的规则），toast 说明「已删除方案「X」，已切换到「Y」」。
- 删空整栏：列表显示 `.psel-none`「暂无方案，可从下方新建。」，触发器显示「暂无方案」，`恢复内置方案` 出现在页脚。

**副本落位规则**

- 源项是自定义方案 → 副本紧跟源项（`list.splice(i+1, 0, p)`）。
- 源项是内置方案 → 副本落在**内置组之后、自定义组开头**，即整组内置方案的正下方。
- 重名规则：`copyName()` 先剥掉已有的「 副本」后缀再追加一次，复制副本得到 `Command Deck 副本 副本`，不会出现四层叠加。

**不变量**

- **选中终端自定义方案不会清空高亮规则**：内置预设切换是「整体替换设置对象」（`theme_settings.dart` 的 `oneDark()` / `solarized()` 直接带 `regexHighlights: []`），而自定义方案记录的就是当前状态，切换应保持规则不变。
- 两栏各自独立：选择、隐藏表、自定义集合都按 `ui` / `term` 分开存，切终端方案不动界面主题，反之亦然。

**无障碍**：触发器 `aria-haspopup="menu"` + `aria-expanded`；列表 `role="menu"`，行容器 `role="none"`，选择项 `role="menuitemradio" aria-checked`，删除项 `role="menuitem"` 且带 `aria-label`；Tab 序列覆盖触发器与列表内全部控件。

**持久化**

| 键 | 内容 | 说明 |
| --- | --- | --- |
| `deepssh.uiPresets` / `deepssh.termPresets` | `[{id,name,sw}]` | 用户方案，顺序即显示顺序 |
| `deepssh.uiHiddenPresets` / `deepssh.termHiddenPresets` | `[id]` | 被移除的内置方案 id |

落地时 `id` 需与 `ThemeSettings` 的枚举/键对齐，`sw` 用作列表色块预览；两个集合建议落在 `prefs` 的 `custom_ui_themes` / `custom_term_themes` 与 `hidden_builtin_themes`。

**差异说明**：源码 `theme_config_page.dart` 目前只有固定预设下拉，选项行没有删除入口，也没有用户方案集合；本节是原型提出的增量需求。

## 8. 正则高亮规则（重点规格）

源码依据：`lib/features/theme_config/theme_config_page.dart:965 _RegexRuleRow`、`theme_settings.dart:5 RegexHighlight`、`rust/src/theme.rs:59`。

### 8.1 数据模型

```dart
class RegexHighlight {
  final String pattern;  // 正则表达式
  final Color  color;    // 命中后着色的颜色
  final String note;     // 备注，仅用于识别
}
```

Rust 侧同名结构体（`rust/src/theme.rs`），以 `theme_settings.yaml` 落盘：

```rust
pub struct RegexHighlight { pub pattern: String, pub color: String, pub note: String }
```

**列表顺序即优先级**：越靠上优先级越高；同一次匹配中，先命中的规则获得着色权，被覆盖的片段不再二次着色。

### 8.2 行结构

行高 **40px**（输入框 32px + 8px 下间距），内部为单行五列，列间距 8px：

| 列 | 宽度 | 控件 | 说明 |
|---|---|---|---|
| 1 | 18px | 拖动柄 | 6 点竖排图标，`cursor: grab`，可聚焦 |
| 2 | ≤280px | 表达式输入框 | 等宽 11.5px，占位符「正则表达式」 |
| 3 | ≤150px | 备注输入框 | 无衬线 12.5px，占位符「备注」 |
| 4 | auto | 紧凑取色器 | 24×24 色块 + Hex 文本 + 展开箭头，整体高 32px |
| 5 | 32×32px | 移除按钮 | 关闭图标，hover 转 `--danger` |

三处细节必须保留：

- 拖动柄 tooltip 为「拖动调整优先级」，并附带当前名次（第 N 条）——名次是这套原型新增的可读性增强。
- 输入框 **默认可直接编辑**，不需要先点「编辑」；`onChanged` 即写回设置对象。
- 移除按钮尺寸固定 32×32px（源码 `BoxConstraints.tightFor(32, 32)`），保证触控目标达标。

### 8.3 默认规则（`TerminalThemeSettings.commandDeck()`）

| # | pattern | note | color |
|---|---|---|---|
| 1 | `ERROR\|FATAL\|Exception\|Traceback` | 错误日志 | `#F14C4C` |
| 2 | `WARN\|WARNING` | 警告日志 | `#F5F543` |
| 3 | `SUCCESS\|OK\|DONE` | 成功状态 | `#23D18B` |
| 4 | `\b[45]\d\d\b` | HTTP 错误 | `#F14C4C` |
| 5 | `\b\d+ms\b\|\b\d+\.\d+s\b` | 耗时 | `#29B8DB` |
| 6 | `\b(?:\d{1,3}\.){3}\d{1,3}\b` | IP 地址 | `#D670D6` |
| 7 | `\b[0-9a-fA-F]{8}(?:-[0-9a-fA-F]{4}){3}-[0-9a-fA-F]{12}\b` | UUID | `#3B8EEA` |

`oneDark()` 与 `solarized()` 的 `regexHighlights` 为**空列表**。因此：

- 切换终端预设会**整体替换**规则列表（源码是 `_updateTerm(preset)`，整个设置对象被换掉），不是合并。
- 列表为空时展示空状态：「当前预设没有高亮规则」，并说明 `regexHighlights` 为空列表、按从上到下顺序匹配。此时预览区无着色。

「添加规则」追加一条 `{pattern: "", note: "", color: #FFFFFF}`（源码默认值：空 pattern、空 note、白色），追加后焦点落在新行的表达式输入框。

### 8.4 交互契约

| 交互 | 行为 |
|---|---|
| 拖动柄 pointerdown | 行跟随指针（`translateY`），出现虚线落位指示框；其余行不位移 |
| 拖动中 | 按指针与各行中线比较得出插入位；指示框落在目标槽位 |
| pointerup | 重排列表、`data-i` 重编号、toast 提示「已把「备注」移到第 N 位」、焦点移到新位置的拖动柄 |
| Alt/Ctrl/⌘ + ↑/↓ | 键盘移动优先级（原型增强，源码仅有指针拖动） |
| 表达式 / 备注输入 | 立即写回状态并触发预览重绘，不做防抖 |
| 取色器 | 点击展开浮层：原生取色控件 + Hex 文本输入（6 位，非法值忽略并保持原值）+ 7 个预设色板；点外部或 `Esc` 关闭；同步 `aria-expanded` |
| 移除 | 立即删除该行并重编号，toast 提示 |

拖动必须用 Pointer Events + `setPointerCapture`，并且在不支持的宿主里做能力检测降级（`if (grip.setPointerCapture) …`）。禁止 `scrollIntoView`（会破坏嵌入式预览）。

### 8.5 无障碍

- 每个输入框、移除按钮、拖动柄都有 `aria-label`，序号随重排更新。
- 拖动柄是真正的 `<button>`，可 Tab 聚焦，`:focus-visible` 有 2px 赤陶描边。
- 落位指示框 `aria-hidden`，纯视觉。

## 10. 交互状态与对比度契约

所有可交互元素必须定义默认 / hover / focus / active / disabled 五态，且：

- 状态切换只改背景（OKLch L 通道 ±0.06–0.12）、描边、阴影或位移，**不得**把前景改成 `--muted` 或任何更接近背景的颜色。
- 正文对比度 ≥ 4.5:1，大字与图标 ≥ 3:1；`--danger` 文字在白底 5.10:1、纸底 4.85:1。
- 实心按钮反色时，前景与背景必须在同一条规则里互换。
- disabled 是唯一允许降低对比度的状态。
- 每个可聚焦元素都要有清晰的 `:focus-visible` 焦点环（2px `--accent`，偏移 1px）。
- 触控目标 ≥ 44px（桌面端密集控件可 32px，但删除 / 关闭类破坏性操作保持 32×32 以上且周围留白充足）。
